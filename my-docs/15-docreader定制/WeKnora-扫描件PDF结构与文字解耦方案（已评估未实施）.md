> **状态：已评估，未实施。** 现行方案是 **PP-StructureV3**（见
> `PP-StructureV3-接入与运维（南宁110）.md`）—— 它把本方案想做的大部分事情已经做好了。
>
> 本文档保留两点价值：
> ① **为什么没走这条路**（避免以后再评估一遍）；
> ② **§三 的接口契约设计** —— 那是「让 LLM 参与但不让它污染文字」的通用手法，
> 与具体方案无关，可复用到别处。

## 一、命题（老魏提出）

> 把「文字识别」与「结构识别」拆成**两条独立通道** ——
> **文字用 PP-OCRv6，结构用小体量 LLM/VLM，且 LLM 识别出的文字一律不使用。**

**它的价值主张**：文字准确率由 PP-OCRv6 保证（不受模型规模影响），
而结构质量可以用**极小体量的模型**换取 ⇒ 两者互不牺牲。

**依据**（两份实测的互补关系）：

| 能力 | PP-OCRv6（实测） | 小 VLM `minicpm-v4.6:1b`（实测） |
|---|---|---|
| **文字** | ★★★ 均分 0.99+，37 个数字 0 错 | ✗ 崩：`工业**化**发展中心`、`**链管**单位`、`**454**.38`（应 254.38） |
| **排版** | ✗ 只给文本行，46 行 → 39 碎片段落 | ★★★ markdown 表格、`<td rowspan="10">` |

## 二、为什么没走这条路

**① 成熟框架里已有现成实现，且更强 —— 用「专用版面模型」而不是通用 LLM**

| | 专用版面检测模型（YOLO / RT-DETR / rf-detr） | 通用 LLM 判结构（本方案） |
|---|---|---|
| 速度 | 单页**几十毫秒** | 估 1~3 s |
| 体积 | **几十 MB** | 数 GB |
| **幻觉** | **结构性不存在**（只输出「类别 + 框」，本就不产出文字） | 需靠契约约束 |

⇒ **本方案在 §三 用契约才换来的「无幻觉」，专用检测器天生具备。**
判据：**能用专用版面模型，就不要用通用 LLM。**

**② PP-StructureV3 已经把「结构 + 文字 + 阅读顺序」一次给全**，且零代码接入
⇒ 自研的边际收益不足以覆盖其成本。

**③ 自研的编排与融合成本被低估**：区域↔文本行归属、阅读顺序排序、
单元格↔文本行匹配、多模块调度 —— 这些在 PP-StructureV3 里**都已经做好了**
（其中「用单元格几何切分 OCR 结果」甚至由官方 `use_ocr_results_with_table_cells` 提供）。

> 先例调研（三层架构 / MinerU 各后端 / 2026 年「合并 vs 解耦」的反转 /
> 其他开源实现）已并入 `WeKnora-扫描件PDF解析质量对比与选型.md` §六。

**唯一仍值得考虑的场景**：需要「专用版面模型覆盖不到的**语义结构**」时
（例如区分「问题描述」与「整改情况」这类**文档级标签**）—— 那是另一类任务，不是版面检测。

## 三、★ 保留价值：让 LLM 参与但不污染文字的「契约设计」

**核心思路：把模型的输出面压到最小 —— 不让它说一个字。**

### 3.1 输入（文本形态，可不需要视觉）

```
页 6/38 · 图 1414x2000 · 共 46 行
id | y     | x    | h     | text
0  | 0.048 | 0.217| 0.018 | 中央部门单位2025年度预算执行等情况审计结果
1  | 0.093 | 0.135| 0.018 | 2025年9月至2026年1月，审计署重点审计了39个部门...
```

坐标**归一化到 0~1**（省 token；与分辨率无关，换 DPI 不影响）。

### 3.2 输出：**每行一个枚举标签**（不输出任何正文）

```
0:T
1:P
2:P
3:H1
```

| 标签 | 含义 | 融合后 |
|---|---|---|
| `T` / `H1` / `H2` | 主标题 / 一级（「一、」）/ 二级（「（一）」）小标题 | `#` / `##` / `###` |
| `S` / `P` | 正文**段首** / 正文**续行** | 起新段 / 与上一行**直接相连** |
| `R` / `D` | 表格表头行 / 数据行 | 进表格 |
| `N` | 页码 / 页眉页脚 | **丢弃** |
| `C` | 图注 | 普通文本 |

### 3.3 为什么这样能**彻底消除幻觉**

| 机制 | 效果 |
|---|---|
| LLM 输出的**文字一律丢弃** | 幻觉**没有进入结果的通路** |
| 只接受**枚举标签** | 非法值可检测 ⇒ 可回落 |
| **行号一一对应**（一行一标签） | 不可能漏行 / 多行 / 错位 |
| 覆盖率 100%（结构上保证） | 无需额外校验 |

⇒ **文字准确率的下界 = PP-OCRv6 的准确率**，与纯 OCR 现状**完全一致**。这是该设计的核心安全性质。

### 3.4 分工原则（可复用）

- **LLM 只标「哪些行属于表格」**（`R`/`D`），**列边界交给几何** ——
  在表格区域内对各行块的 `x1` 做聚类（带容差）。
  理由：表格是**规整对齐**的，x 聚类非常可靠；而让 LLM 输出单元格归属（嵌套结构）既易错又费 token。
- **各做各擅长的部分** —— 这是整个设计的组织原则。

## 四、若将来要实施（待验证项）

1. **「文本 + 坐标」是否足以判结构** —— 最大假设；若不足则必须补视觉输入
2. 小模型的**格式遵守度**（能否稳定按契约输出）
3. 速度（只出标签约 200 token，应显著快于输出整页文本）
4. 表格列聚类的鲁棒性（跨行单元格、无竖线的三线表）
5. 跨页表格的续接
