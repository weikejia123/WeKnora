1先搞清楚：它是什么，不是什么

最常见的误解

很多人以为「浏览器技能」是服务端开了个无头浏览器（Headless Chrome）在替你上网。不是。服务端没有替你上网的浏览器——它只是个中转站。真正在打开网页的，是你自己电脑上那个 Chrome。

这个区别不是文字游戏，它决定了三件很实际的事：

对比项服务端无头浏览器（如果有的话）本机浏览器技能（实际实现）
浏览器在哪服务器上你的电脑上
登录态空的，谁也没登录你的——Cookie、已保存的密码都在
内网系统通常访问不到能访问（因为走的是你的网络）
遇到验证码只能卡住弹给你，你扫一下就过
所以它真正的价值：能进「需要登录才能看」的页面。企业内网、后台系统、付费内容、需要扫码登录的站点——这些是普通联网搜索永远够不到的地方。

三种取网页的能力，别用混了

WeKnora 里跟「上网」有关的能力有三套，边界各不相同：

能力能拿到什么登录态适合什么
联网搜索
web_search		搜索结果条目的标题、链接、摘要片段无找线索：「这件事有没有公开报道」
网页抓取
web_fetch		把公开页面正文转成 Markdown无读内容：「这篇公开文章说了什么」
本机浏览器
local_browser		完整网页：可点击、填写、翻页、截图有办事情：「登录后台把这张表导出来」
ⓘ 怎么选：只是在找公开资料，用前两个就够了，快得多。只有当前两个都不行——页面要登录、要交互、在内网——才值得启用本机浏览器。

典型场景

  • 内网站点取数：登录公司业务系统，翻到某张报表，把数据读出来
  • 需要多步交互的查询：填表单、选下拉、点「查询」，再读结果
  • 抓取登录后才可见的内容：会员文章、后台订单、需要扫码的页面
  • 页面长截图取证：图表、看板这类「只有渲染出来才有意义」的内容

2协同架构：三方两段

整条链路上有三个角色，两段连接。先看图，再逐个解释。

角色在哪干什么
配套扩展你的 Chrome接收指令、操作真实标签页、把页面画面和文字传回
网关服务器验证你的身份、转发指令、管理「谁在控制哪个任务」
bsk 后台进程服务器把智能体的动作翻译成浏览器能听懂的指令
ⓘ 为什么服务端还要跑一个后台进程？因为它负责把「点这个按钮」翻译成浏览器底层协议（CDP）的指令，还要管理任务窗口、标签借用这些状态。它是 Rust 写的原生程序，由服务进程自动拉起，用随机端口，你不用管它。

3四步上手

第 1 步 · 安装扩展

  1. 进入 个人设置 → 浏览器连接
  2. 点「下载扩展」，得到一个 ZIP 包
  3. 解压到一个不会随手删掉的文件夹（重要：解压目录要保留，Chrome 是从这个目录加载的）
  4. 打开 Chrome 的 chrome://extensions，右上角开启开发者模式
  5. 点「加载已解压的扩展程序」，选刚才解压的文件夹
必须下载本服务提供的配套包：官方原版扩展不包含 WeKnora 需要的任务控制接口，装错了会报「扩展缺少任务控制」。另外——扩展升级后要重新下载覆盖，光重启服务端不会更新你浏览器里的扩展。

第 2 步 · 配对这台浏览器

  1. 还是在设置页，点「连接这台浏览器」→「复制配对链接」
  2. 打开扩展的「远程连接」，粘贴链接并确认
配对链接长什么样？
wss://你的域名/api/v1/local-browser/extension#一串令牌
井号后面那串就是令牌，5 分钟内有效，只能用一次。
ⓘ 配对一次就够：同一个空间下的所有对话共用这台设备的授权，不需要每个对话配一次。换电脑或换浏览器才需要重新配对。

第 3 步 · 回到对话描述任务

在输入框打开「本机浏览器」开关，然后像对人说话一样描述任务：

「登录 XX 系统，进入订单管理，把今天的所有订单导出来」
「打开这个内网站点，找到 2024 年的统计报表，把数字读出来」
「去这个页面看看现在的实时价格是多少」

发送后，Chrome 里会打开一个带标识的独立任务窗口，智能体在里面操作。这个窗口不会抢走你正在看的页面的焦点。

第 4 步 · 通过预览跟进

对话里会出现一个小预览窗，实时显示浏览器画面（约每秒一帧）。它可以拖动，也可以点标题栏的「弹出悬浮窗」变成置顶小窗。

下面这些情况需要你出手，第 5 章详解：

  • 页面要登录 / 要输验证码 → 智能体会「等待你操作」
  • 智能体想用你已经打开的某个标签页 → 会请你授权
  • 你想中断它 → 点「暂停操作」

4配对为什么是安全的

让一个网页服务来操作你的浏览器，听起来风险不小。所以配对这一步做了三重保护：

措施效果
只存哈希服务器数据库里存的是令牌的哈希值，不是令牌本身，泄露库也拿不到令牌
5 分钟 · 单次链接过期即废，用过一次就失效
独占租约同一时间只有一台服务器节点能持有这台浏览器的连接，不会两边同时指挥
随时撤销设置页「撤销设备授权」立即失效，之后要重新配对
ⓘ 令牌存在哪？令牌只存在你浏览器扩展自己的存储里，不会同步到 WeKnora 账号，也不会写进浏览器历史（因为它在井号后面）。所以换浏览器Profile、清扩展数据，都需要重新配对。

5三种协同场景

智能体和你的浏览器之间，有三种不同亲密度的协作方式。

场景一 · 独立任务窗口（默认，最常见）

你发一个任务，Chrome 里打开一个带标识的独立窗口，智能体在里面自己开页面、点、填。

  • 不抢焦点：不会把你正在看的页面顶掉
  • 共享登录态：虽然是新窗口，但用的是同一个 Chrome，Cookie 是通的
  • 用完即清：任务正常结束时，它新建的标签会被关闭
你什么都不用做：除非页面要登录或验证码，否则整个流程不需要你介入。

场景二 · 借用你已经打开的标签页

有时候智能体需要操作你已经打开的某个页面（比如你已经登录好、筛选好的那个后台列表）。这时它不能直接用——得先借。

两个容易搞混的点
① 「继续操作」不等于「同意借用」。点继续只是恢复被暂停的任务，借用授权必须在目标页面上单独点「允许」。
② 借用被拒绝后，不要反复重试。智能体被拒绝后应该换办法或向你说明，而不是不停请求借用。

场景三 · 人工接管（登录、验证码）

遇到登录、短信验证码、图形验证码、二次授权这类只有人能过的关卡，智能体会主动停下来交给你。

记住这两条
① 「调用成功」不等于「登录成功」。智能体收到你确认后，必须重新看一眼页面才能继续；它不会凭页面上出现「欢迎」两个字就宣布登录成功。
② 等待上限 5 分钟。超时或取消会保留页面并暂停任务，你在预览里点「继续操作」就能接着来，不需要重新配对。
ⓘ 为什么有时候「没有弹出提示」？人工接管必须由智能体主动发起才会显示。如果它只是在回复里写了句「请登录后告诉我」，那是它没按规矩来，不会有任何提示，页面也不会保留。这时可以直接提醒它：「调用 request_help」。

三种收尾方式

方式发生时机页面怎么处理
自动回收
默认		一轮任务顺利做完关闭任务新建的标签，归还借用的标签
保留
keep_open		你要留着这个页面（表单没填完、要你自己看）整项任务原样保留，下一轮继续用

7预览小窗：你的控制台

对话里那个小窗口是你观察和控制任务的唯一入口。

按钮

按钮作用
定位到浏览器跳到 Chrome 里的任务窗口
暂停操作中断当前浏览器操作，保留页面；不会停止整段对话
继续操作恢复被暂停的任务，在同一对话里接着来
结束浏览器任务关闭任务新建的标签、归还借用的标签；不会关闭 Chrome，也不会撤销配对
弹出悬浮窗把预览和按钮移到置顶小窗，方便边看边操作

画面状态

显示含义
画面同步中正在实时刷新
已保留最后画面这一轮结束了，画面定格
画面暂未更新超过 5 秒没拿到新画面，检查扩展是否正常
等待任务页面任务刚发起，页面还没创建好
预览不是视频：它是约每秒 1 帧的低帧率截图同步，用来「知道在干嘛」，不适合看动画或快速变化的画面。要看清细节，让智能体用 screenshot 截高清图。

8智能体能做哪些动作

工具名是 local_browser，一共 26 个动作。你不需要记住它们——只要知道它能干什么，描述任务时说人话即可。

类别动作
看observe 页面文字和可操作元素 · snapshot 结构快照 · screenshot 截图 · get_html 源码
走navigate 打开网址 · navigate_back / navigate_forward 前进后退 · reload 刷新
动click 点击 · fill 填写 · press 按键 · hover 悬停 · select 选下拉 · focus / blur
滚wheel 滚动 · scroll_to 滚动到某元素
管标签tab_list 列出 · tab_create 新建 · tab_select 切换 · tab_close 关闭 · tab_borrow 借用 · tab_return 归还
等wait_for_navigation 等跳转 · wait_ms 等一会儿
调试evaluate 执行脚本 · console 看控制台 · network 看网络请求 · window_resize · emulate 模拟设备
找你request_help 请你操作
ⓘ 它怎么「看见」页面？不是靠猜坐标。它会先用 observe 把页面扫一遍，给每个可操作元素编个号（比如 e3），然后说「点 e3」。所以页面变了之后要重新 observe，否则会点到旧元素。

9排错指南

现象原因怎么办
「服务端尚未启用本机浏览器」服务端没配置找管理员，见第 10 章
「管理员尚未配置扩展下载包」扩展包路径没配找管理员要配套版本的 ZIP
配对链接用不了5 分钟过期或已用过回设置页重新复制一次
扩展连上就断Chrome 关了或扩展被禁用保持 Chrome 和扩展开启，它会自动重连，不用重新配对
「扩展缺少任务控制」装的是官方原版扩展下载本服务提供的配套 ZIP，覆盖后重新加载
任务一直暂停人工步骤超时或你中断过点预览里的「继续操作」
借用标签总失败没在目标页面点允许切到那个页面，在提示里点「允许」；拒绝后别反复重试
登录页弹了但没提示智能体没调用 request_help提醒它「调用 request_help」
画面卡住不动预览取不到画面看是否显示「画面暂未更新」，检查扩展；必要时结束任务重来
排错第一原则：绝大多数问题不需要重新配对。重新配对是最后手段——它会让所有进行中的任务失效。先试「继续操作」，再试刷新页面，最后才考虑撤销授权重新配对。

10管理员：启用前必须满足的条件

这一章给部署和维护的人看。

硬性前提：镜像里得有这两个文件

BROWSERSKILL_BINARY=/opt/weknora/browserskill/bsk
BROWSERSKILL_EXTENSION_PATH=/opt/weknora/browserskill/browser-skill-weknora-0.3.0.zip

这两个文件由官方 docker/Dockerfile.app 的独立构建阶段生成：从 Tencent/BrowserSkill 固定提交克隆源码 → 应用 patches/browserskill/*.patch → 用 Cargo 编译。构建需要 Rust/Cargo、Node、C 编译器（Linux 还需 CMake），以及能访问上游源码和依赖的网络。

最容易踩的坑：旧版 app 镜像里没有 /opt/weknora/browserskill/ 这个目录，功能等于没启用，界面只会显示「服务端尚未启用本机浏览器」。升级镜像后要用 docker compose up -d app 重建容器——restart 不会加载新环境变量。

配置

变量默认说明
BROWSERSKILL_BINARY镜像已预设bsk 可执行文件路径；设为空可关闭此功能
BROWSERSKILL_EXTENSION_PATH镜像已预设供用户下载的扩展 ZIP
BROWSERSKILL_PUBLIC_URL不设通常不必配——默认从用户页面地址推导（HTTPS→WSS）。仅网关独立域名等特殊情况才设
BROWSERSKILL_MAX_CONNECTIONS32单个服务实例保留的配对数上限
BROWSERSKILL_INTERNAL_URL不设多副本才需要：填各节点可直连的地址，不能用负载均衡地址
BROWSERSKILL_CLUSTER_SECRET不设多副本才需要：所有副本用同一个随机串，至少 32 字符

网络与部署

  • 远程部署必须 WSS（即必须先有 HTTPS）。内网可用企业 CA 证书
  • 外层还有 Ingress/Nginx 时，要为扩展路径转发 WebSocket 升级
  • 直接暴露 app 的部署，须自行屏蔽公网对 /api/v1/local-browser/internal 的访问
  • 本机调试可用 ws://localhost:8080/api/v1/local-browser/extension

扩展升级

扩展版本更新后，即使版本号没变（例如同是 0.3.0 但源码基线变了），也要通知用户重新下载 ZIP、覆盖原解压目录、在扩展页面重新加载。只重启服务端不会更新用户浏览器里的扩展。保持原扩展 ID 时，旧的本地凭据会自动迁移；如果重装导致 ID 变了，用户必须重新配对。
