# BrowserSkill 本机浏览器技能：机制解析与使用定位

> **更新时间**：2026-11-04 ｜ **版本**：v1
>
> **定位**：回答"111 服务器上的 WeKnora，凭什么能用我本地的浏览器？"这个方向性问题，
> 并界定它在我们实际使用中的价值。**操作步骤不重复**——详见同目录《WeKnora-本机浏览器技能使用手册.html》。
> 依据：`internal/browserskill/`、`internal/agent/tools/browserskill*.go`、`scripts/build_browserskill.sh`、官方 `website-docs/05-clients/09-local-browser.md`。

## 一、先纠正方向：不是"111 控制你的浏览器"，是反过来

**连接方向是：你本地的 Chrome → 主动连到 111。** 不是 111 来连你。

| 环节 | 在哪 | 谁主动 |
|---|---|---|
| Chrome + BrowserSkill 扩展 | **你的本地电脑** | 扩展**主动向外**发起 WSS 连接到 111 |
| 网关 + bsk 后台进程 | 111 上的 WeKnora 容器 | 被动接受连接、鉴权、转发 |
| 智能体（local_browser 工具） | 111 上的 WeKnora | 把"点/填/截图"等**指令**发给你本地扩展 |

所以：

- **你的本地电脑不需要开任何端口、不需要公网 IP**——是扩展从内网往外连，NAT 后面没问题。
- 111 需要的是**对外的 WSS 入口**（经 weknora-nginx 的 TLS，即 41200/10443 那条链路），配对链接就是 `wss://…/api/v1/local-browser/extension#令牌`。
- **登录态、页面内容始终留在你本地**：传到 111 的只是截图画面和页面文字。111 上没有替你上网的无头浏览器。

一句话模型：**111 是"大脑"，发指令；你本地 Chrome 是"手"，执行；扩展是"神经"，双向传。**

## 二、知识库里/智能体加这个有什么用？

核心价值一句话：**让智能体进"需要登录才能看、需要点选才能取"的页面。**

WeKnora 有三套"上网"能力，边界要分清：

| 能力 | 拿到什么 | 登录态 | 适合 |
|---|---|---|---|
| 联网搜索 web_search | 搜索结果摘要 | 无 | 找线索 |
| 网页抓取 web_fetch | 公开页面正文 | 无 | 读公开文章 |
| **本机浏览器 local_browser** | 完整可交互网页 | **有（你的 Cookie）** | **登录后台办事、内网取数** |

对知识库的实际意义：

1. **入库侧**：内网系统、付费内容、登录后可见的资料——web_fetch 抓不到，本机浏览器能取到后再入库。
2. **问答侧**：问答过程中需要"实时去某个登录系统查一下"（如业务系统里的最新数据），智能体现场操作你浏览器取回。
3. **只有渲染才有意义的内容**：图表看板截图等。

**判断口径**：公开资料用前两个，快得多；只有前两个够不到（登录/交互/内网）才动用本机浏览器。

## 三、使用要点（速记）

1. **四步**：装扩展（设置页下载 ZIP → chrome://extensions 加载已解压）→ 配对（粘贴一次性链接，5 分钟单次有效）→ 对话里打开"本机浏览器"开关、用人话描述任务 → 预览小窗跟进。
2. **配对一次就够**：同一空间所有对话共用；换电脑/浏览器才重配。
3. **遇到登录/验证码**：智能体会暂停并交还给你（上限 5 分钟），你操作完确认即可，不用重新配对。
4. **借用标签要授权**：智能体操作你已打开的页面须你在该页面点"允许"，用完 `tab_return` 归还原位。
5. **扩展升级后要重新下载覆盖**——重启服务端不会更新你浏览器里的扩展。

## 四、我们部署（111）下的注意点

- **上游源码本地有克隆**：`my-other-git/BrowserSkill`（remote=github.com/Tencent/BrowserSkill，已由根 `.git/info/exclude` 排除、不入版本控制）。2026-11-04 已拉取更新至 `c134fbb6`（2026-11-03，较克隆时前进 489 个提交，扩展源码版本 0.4.1）。
- ⚠️ **看更新 ≠ 直接用最新**：WeKnora 构建时 pin 的是 `0.4.1`（`scripts/browserskill-release.json` 的 `b8f2d4f0`，第 14 轮由 `0.3.1`/`da6bf4ee` 升级），扩展与 app 内 bsk daemon **协议基线必须一致**。直接把仓库最新源码加载进浏览器可能报协议不匹配（高于 pin 也一样）。要看更新用 `git log`；要用扩展，以 WeKnora 设置页「下载扩展」的 ZIP 为准（构建脚本 `scripts/build_browserskill.sh` 会自行拉取 pinned commit，不依赖本目录）。
- ⚠️ **0.3.1 扩展已过期**：前端 `MIN_EXTENSION_VERSION = '0.4.1'`，旧扩展会被提示升级且链路不可用。已加载 0.3.1 的浏览器须在**新版 app 镜像起来后**重跑 `my-scripts/pack_browserskill_ext.sh` 取 0.4.1 的 ZIP 并重新加载。
- WSS 入口经 `my-docker/nginx/`（TLS）；配对链接域名/端口以 111 当前 nginx 配置为准（入口 41200/10443，见 `00-111部署快照.md`）。
- 安全模型（手册第 4 章）：令牌只存哈希、5 分钟单次、独占租约、可随时撤销——让服务端操作浏览器这件事的风险被配对环节收窄。

## 五、扩展获取/打包（固化流程）

打包脚本：`my-scripts/pack_browserskill_ext.sh`
- 默认：从 111 的 `WeKnora-app` 容器取现成 ZIP 并解压到 `my-other-git/browser-skill-weknora-<版本>/`（推荐——与服务端 daemon 版本天然一致）。
- `--build`：从源码按 pinned commit 本地构建（需 pnpm，慢，一般不用）。
- **服务端升级后重跑一次**，然后在 `chrome://extensions` 里刷新/重新加载即可。
- 加载动作由人工在 Chrome 完成；目录根下应有 `manifest.json`。
