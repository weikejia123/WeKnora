1结论速览（TL;DR）

定位
跨会话、跨会话的个人长期记忆：记住一个 principal 在某个 workspace 内的稳定事实、偏好、任务、关注主题与文档依赖，让不同会话间的回答保持一致，并作为个人化检索信号。
核心设计
「范围隔离 + 读写双路径 + 后台蒸馏 + 整库整合 + 一致性保障」五层结构：读路径零模型调用、永不报错；写入经统一 writeReplacing 保证清洗/脱敏/冲突/容量/向量一致。
可靠性
后台蒸馏走 asynq 队列 + 租约串行化 + watermark 推进，不丢消息；推断性记忆进入 pending 待确认，遗忘用「指纹+来源消息」双重墓碑抑制重蒸馏。
一致性
由范围解析、generation 围栏、事务替换关系、唯一索引、租约恢复、容量治理共同保障，并有专门的回滚/恢复一致性测试覆盖。

2记忆系统的业务定位与设计目标

2.1 业务定义

记忆系统是 WeKnora 的个人长期记忆层：它把「一个问题对这个人意味着什么」从知识库的通用检索中剥离出来，记住一个人在某个 workspace 内跨会话稳定存在的事实（fact）、偏好（preference）、任务（task）、关注主题（interest）与文档依赖（affinity），使不同会话之间的回答保持一致，并在知识库检索前注入个人化条件，让同一问题对不同人产生不同检索结果。

2.2 与知识库的关系

记忆与知识库是正交的两个维度：

  • 个人化层：记忆提供 RetrievalContext（background/interests/documents），在检索前改写查询、个性化文档排序，解决「同一问题对不同人意义不同」的问题。
  • 持久信号层：记忆中的文档亲和度（memory_doc_affinity）与熟悉文档列表，让个人偏好在知识库中可持久表达（Wiki 高亮、reranker 加权）。
  • 不替代知识库：记忆是「关于人的记忆」，知识库是「关于主题的知识」，二者互不覆盖。

2.3 与通用记忆系统（ChatGPT background layer / Graphiti / mem0 等）的差异

维度通用记忆系统常见做法WeKnora 记忆系统的做法
写入可审计推断性记忆静默写入推断性记忆（inferred）进入 pending 状态，必须用户确认才生效，避免静默错误断言
遗忘精确性删除可能连带丢弃内容只记录 topic + fingerprint + 来源消息的墓碑，用指纹+来源消息双重抑制重蒸馏
读路径延迟召回可能涉及模型调用Recall / SearchMemory / RetrievalContextFor 均为纯索引读取，零模型调用，永不阻塞首 token
语义召回直接依赖向量检索词法 + 向量双路 RRF 融合，带最小相关分与预算截断，可降级词法
主题归一按字符串直接匹配主题解析三级（归一化相等→模糊 bigram→模型裁决），避免同一主题被重复计数
全局治理依赖逐轮蒸馏覆盖全局独立整库整合阶段：过期归档、陈旧任务降权、近重复合并、向量回填与同步
隔离安全依赖客户端传入作用域范围从请求上下文推导，不信任客户端 id，杜绝跨主体泄漏

5关键机制说明

范围隔离与开关（三级）
ResolveScope 从请求上下文解析 TenantID + Principal.StorageID，作用域不信任客户端传入；enabledScope 依次检查 workspace MemoryConfig → 用户 Enabled → agent 偏好，任一关闭即降级为「无记忆」，读路径永不报错。
写入一致性（统一 writeReplacing）
显式写入与后台蒸馏都走同一 writeReplacing：先清洗、再脱敏（敏感字段替换为占位符）、校验 kind、做遗忘与冲突检查，再保存、强制容量、重建 resident block、存向量。保证清洗/脱敏/冲突/容量/向量不会因调用方不同而绕过。
遗忘与防重蒸馏（双重墓碑）
删除/清除只记录 topic + 内容指纹 + 来源消息的墓碑，不删除正文；写入前用指纹与来源消息双重检查，抑制「用户删除后后台重新蒸馏出同样内容」的重现；墓碑上限 MaxMemoryTombstones=500，超限丢弃最旧。
推断与确认（pending）
系统推断的关于用户的记忆（inferred）进入 pending 状态，不注入 prompt、不静默生效，必须用户确认才正式启用；拒绝则删除并记录墓碑，避免同一猜测再次被提出。
容量治理（自动遗忘）
enforceCapacity 在主体超出容量上限时归档最低排名的活跃条目；待确认条目另有 pendingLimit 保护；已注入使用的条目通过 touchAsync 计入，避免不可达条目长期占位。
语义与词法融合（降级安全）
召回同时走词法打分与向量 RRF 融合，词法池随当前容量上限动态扩展；minCosine=0.5 过滤零匹配；读侧 embed 超时（2s）自动降级为纯词法匹配，保证首 token 不被阻塞。
后台蒸馏可靠性
ScheduleExtraction 只排队不丢消息（turn 始终记录，定时器只决定何时执行）；Handle 用租约串行化并发、watermark 推进会话、分段按 1h 静默切分、截断输出重试、命中上限后排队跟进任务、释放租约后由重投递恢复。
整库整合与一致性收尾
每日（24h）或手动（1min）触发整库整合：过期归档、45 天未使用任务降权、近重复聚类后交给模型合并、补向量、同步向量列、重建 block；合并采用「写新+supersede 旧」保留旧日期可解释变更。

6质量保障与测试

测试覆盖
service_test、extract_test、lexical_test、vector_test、search_test、topic_resolve_test、consolidate_test、consistency_test、regression_test、coverage_test、admin_test 等，覆盖写入、读取、主题解析、整合、向量、管理全路径。
一致性测试（专门保障）
事务回滚（失败替换不得留下新行）、租约恢复保留进度、重投递等待崩溃 worker 租约、迁移恢复 legacy pending、消息分页不重复、墓碑边界等；并包含 Postgres 迁移恢复测试。
可靠性保障
结构化输出解析（容忍代码块/杂文本）、截断重试、模型不可用降级、范围缺失即丢弃、队列/租约异常不阻塞正式数据、敏感内容脱敏与「几乎全被脱敏则丢弃」双重保护。
质量门禁
回归测试、覆盖率测试、一致性测试、迁移测试共同构成质量保障；所有关键路径均有可核对的测试与日志埋点。

7结论与落地建议

结论：WeKnora 的记忆系统是面向个人长期记忆的完整子系统，具备「范围隔离、读写双路径、后台蒸馏、整库整合、一致性保障」的完整闭环，读路径零模型调用、写入路径统一且可审计、遗忘与推断可精确控制、后台任务有租约与队列保障、一致性有专门测试与迁移保障，在个人化检索与跨会话一致性场景下设计完整，且具备良好的可维护性与可降级性。

后续可关注的方向（基于代码演进点）：

  • 向量回填与向量列同步可按主体分片批量推进，进一步降低大容量主体的维护成本；
  • 整合合并的候选上限与合并阈值可按主体规模动态调整，平衡合并收益与模型调用成本；
  • 词法召回池随容量动态扩展（当前固定为当前容量上限），可进一步优化大容量主体下的召回覆盖；
  • 主题解析的 tier3 模型裁决可增加缓存，减少重复的模型往返。
