# 扫描件 PDF「结构 / 文字解耦」方案（草稿）

> **状态**：草稿 —— 由推理得出，**尚未实验验证**（老魏 2026-09-22 指定「分析即可，不用做实验」）。
> **命题**（老魏提出）：把「文字识别」与「结构识别」拆成两条独立通道 ——
> **文字用 PP-OCRv6，结构用小体量 LLM/VLM，且 LLM 识别出的文字一律不使用。**
>
> 前置依据：`WeKnora-扫描件PDF解析质量对比与选型.md`（两份实测对照）。
> 落点：仅 `my-docreader/`（自研目录），**不改任何官方文件**。

---

## 一、为什么这个命题成立

上一轮实测暴露了一个**互补关系**：

| 能力 | PP-OCRv6（实测） | 小 VLM `minicpm-v4.6:1b`（实测） |
|---|---|---|
| **文字** | **★ ★ ★** 均分 0.99+，37 个数字 0 错 | **✗** 崩：`工业**化**发展中心`、`**链管**单位`、`**454**.38`(应 254.38) |
| **排版** | **✗** 只给文本行，46 行 → 39 碎片段落 | **★ ★ ★** markdown 表格、`<td rowspan="10">` |

⇒ **两者的短板正好被对方的长板覆盖。**

**关键推论**：上一轮我把「1b 模型字准崩」当作**否决理由** —— 那是**在「单一模型承担两件事」的框架下**才成立。
一旦解耦，**1b 的字准缺陷与我们无关**，而它的排版能力仍可用。

> 这正是本方案最大的价值：**可以用极小体量的模型来获取结构，而不牺牲任何字准。**

## 二、两个可进一步降低成本的洞察

### 2.1 结构判断需要的信息，大多不在像素里

我们的几何重组之所以失败，是因为它**只有几何、没有语义**。而 LLM 要做的判断，
所需要的线索**大量已存在于「行文本 + 行属性」中**：

| 结构线索 | 从哪来 |
|---|---|
| 「一、」「（一）」这类编号 | **行文本** |
| 标题（短、不以句读结尾、居中） | 行文本 + `x` 居中 + 行高 |
| 段首缩进（中文公文缩进 2 字符） | `x1` 偏离左边界 |
| 表格行（多个同行独立块、行高偏小） | 多个 bbox 同行 + 行高 |
| 页眉页脚 / 页码 | `y` 极值 + 行文本模式 |

⇒ **有可能不需要视觉输入**：把「行号 + 归一化坐标 + 行高 + 文本」交给一个**纯文本**模型即可。

**收益**：省掉视觉编码器（显存与时延的大头），110 上现成的 `qwen2.5:7b` 就能用。

### 2.2 输出越短越快

整页 markdown 输出约 1100 字符（VLM 实测 14.5 s/页）。而**只输出标签**时，
输出长度约为 **每行 4 token × 46 行 ≈ 200 token** ⇒ 生成时间应显著低于输出整页文本。

⇒ 推测 **1~3 s/页**（待验证）。这是本方案相对「VLM 直接出 markdown」的第二个优势。

## 三、架构

```
                    ┌─────────────────────────────────────────┐
   页面图 ──┬──────►│  PP-OCRv6（110:36741）                   │
            │       │  输出：N 个 (text, bbox, score)         │
            │       └───────────────┬─────────────────────────┘
            │                       │ 文字 + 坐标（**唯一文字来源**）
            │                       ▼
            │       ┌─────────────────────────────────────────┐
            └──────►│  StructureAnnotator（本方案新增）        │
       （可选视觉）  │  输入：行号 + 归一化坐标 + 行高 + 文本   │
                    │  输出：每行一个「结构标签」              │
                    └───────────────┬─────────────────────────┘
                                    │ 标签（枚举值，**不含任何文字**）
                                    ▼
                    ┌─────────────────────────────────────────┐
                    │  Fuser（融合）                           │
                    │  · 按标签分段 / 定标题层级               │
                    │  · 表格区域 → 几何求列边界 → markdown 表 │
                    │  · 文字一律回填 PP-OCRv6 的原文          │
                    └───────────────┬─────────────────────────┘
                                    ▼
                                 markdown
```

**两条通道的边界**：LLM **只输出标签**，一个字的正文都不采纳；
正文字符**全部**来自 PP-OCRv6。

## 四、接口契约（本方案的核心）

### 4.1 送给 LLM 的输入（文本形态）

```
页 6/38 · 图 1414x2000 · 共 46 行
id | y     | x    | h     | text
0  | 0.048 | 0.217| 0.018 | 中央部门单位2025年度预算执行等情况审计结果
1  | 0.093 | 0.135| 0.018 | 2025年9月至2026年1月，审计署重点审计了39个部门...
```

坐标**归一化到 0~1**（省 token；且与分辨率无关，换 DPI 不影响）。

### 4.2 要求的输出：每行一个标签

```
0:T
1:P
2:P
3:H1
...
```

| 标签 | 含义 | 融合后 |
|---|---|---|
| `T` | 页/文档主标题 | `#` |
| `H1` | 一级小标题（「一、」） | `##` |
| `H2` | 二级小标题（「（一）」） | `###` |
| `S` | 正文**段首** | 起新段 |
| `P` | 正文**续行** | 与上一行**直接相连**（不加空行） |
| `R` | 表格表头行 | 进表格 |
| `D` | 表格数据行 | 进表格 |
| `N` | 页码 / 页眉页脚 | **丢弃** |
| `C` | 图注 / 图表标题 | 普通文本 |

### 4.3 为什么这个契约能**彻底消除幻觉**

| 机制 | 效果 |
|---|---|
| LLM 输出的**文字一律丢弃** | 幻觉**没有进入结果的通路** |
| 只接受**枚举标签** | 非法值可检测 ⇒ 回落 |
| **行号一一对应**（一行一标签） | 不可能漏行 / 多行 / 错位 |
| 覆盖率为 100%（结构上保证） | 无需额外校验 |

⇒ **文字准确率的下界 = PP-OCRv6 的准确率**，即**与现状完全一致**。这是本方案最重要的安全性质。

## 五、融合细节

### 5.1 段落与标题
- `N` → 丢弃（页眉页脚页码不进入正文）
- `T` / `H1` / `H2` → 对应层级的 markdown 标题
- `S` 起新段；`P` 与上一段**直接相连**（避免把断句强化成段落边界 —— 这是现有实现踩过的坑）

### 5.2 表格（关键补足）
LLM **不需要**给出单元格归属，只标出「哪些行属于表格」（`R` / `D`）。
**列边界由几何方法求**：在表格区域内对各行块的 `x1` 做聚类（带容差），得到列边界，
再按 `(行, 列)` 填充成 markdown 表格。

> **为什么交给几何**：表格是**规整对齐**的，x 聚类在这种结构上非常可靠；
> 而让 LLM 输出单元格归属（嵌套结构）既易错又费 token。**各做各擅长的部分。**

### 5.3 跨页续接
沿用现有 `join_pages()` 的逻辑：上一页末尾非句读 ⇒ 与下一页首行相连。
新增判据：若上一页末行为 `D`（表格行）且下一页首行同为 `D` ⇒ 表格续接（暂标记为已知限制，见 §七）。

## 六、容错与降级

| 情形 | 处理 |
|---|---|
| LLM 超时 / 连不上 | 整页回落**现有几何重组**（`LayoutRestructurer`） |
| 输出行数与输入不符 | 缺的行标 `P`（保守）；缺失比例 > 20% ⇒ 整页回落 |
| 出现枚举外标签 | 该行标 `P` |
| 表格区域 < 2 行 | 不当表格，按正文处理 |
| 开关关闭（环境变量） | 全量走现有路径（行为与今天完全一致） |

**原则**：**任何一步失败都退回「现状」，绝不产出比现状更差的结果。**

## 七、落点与成本

**改动面**：仅在 `my-docreader/ppocr_converter.py` 内扩展
- 新增 `StructureAnnotator`（调 LLM，含契约解析与校验）
- `LayoutRestructurer` 扩展：接受标签输入，替代/增强现有的几何判据
- 新增 `Fuser`（或直接在 restructurer 内按标签分支）
- 新环境变量：`PPOCR_STRUCT_URL` / `PPOCR_STRUCT_MODEL` / `PPOCR_STRUCT_ENABLED`

**官方文件改动：0 处**（与现状相同 —— 我们的定制本来就在自研目录）✓

| 维度 | 现状（纯几何） | 解耦方案 |
|---|---|---|
| 字准 | ★ ★ ★ | ★ ★ ★（**不变**，有结构性保证） |
| 排版 | ★ ☆ | ★ ★ ★（预期） |
| 速度 | 0.9 s/页 | + Δ（推测 1~3 s/页，待验证） |
| 显存增量 | — | 视模型（纯文本 7B Q4 ≈ 5 GB，按需加载） |
| 幻觉风险 | 无 | **无**（文字不经过 LLM） |
| 可机械校验 | — | **有**（标签数 = 行数、枚举合法） |

## 八、待验证（草稿的边界，勿当作结论）

1. **文本+坐标是否足以判断结构**（§2.1）—— 这是本方案最大的未验证假设。
   若不足，需升级到 L2（带视觉）。
2. **小模型的指令跟随能力** —— 1b 级模型能否稳定输出「每行一个标签」的紧凑格式？
   我们已知 1b 擅长排版判断，但**格式遵守度**未测。
3. **速度**（§2.2 的推测）。
4. **表格列聚类的鲁棒性** —— 跨行单元格、无竖线的三线表。
5. **跨页表格/段落的续接**（§5.3）。

### 建议的验证顺序（若后续要实施）
1. 取 **1 页**跑「标签契约」，看格式遵守度与标签质量（低成本，先证伪）
2. 扩到 **10 页**，与现状几何重组**并排对比**（老魏的偏好：可视化并列对比）
3. 达标后再接进 converter，走 `push-reader`（秒级）→ 真实入库对比

## 九、分级实施建议

| 级别 | 做法 | 成本 | 适用 |
|---|---|---|---|
| **L1** | 纯文本小模型给标签（§2.1） | 最低（无视觉编码） | 先试这个 |
| **L2** | VLM 给标签（带图） | 中 | L1 判不准的页 |
| **L3** | 回落：现有几何重组 | 零 | 兜底，永远保留 |

**建议从 L1 起步**：若它够用，则整条路的成本远低于「VLM 直接出 markdown」；
若不够，再上 L2 —— 而**契约（§四）完全不变**，只是换个模型。

> 即：**先定契约，再选模型**。契约是稳定的，模型可以随时替换。
